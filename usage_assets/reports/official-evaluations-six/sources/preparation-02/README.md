This v2 directory prepares source for a future CPU audit of the six preserved official native evaluations: five final teachers and the pure student at iteration 9999. V1 remains preserved separately: Root rejected its unsupported clip-ID bound and missing strict TensorBoard whole-record gate; its earlier static review is not runtime evidence. The v2 validator has not been executed or imported during preparation. AST/source hashes and actual JSON/YAML field observations are separate evidence; none is a runtime acceptance result.

Invoke inside the guarded CPU Docker container with its installed `train-python`, TensorBoard, PyYAML, `ffprobe`, and `ffmpeg`:

```text
/opt/php/bin/train-python -B /code/validate.py --contract-sha256 <input-contract SHA256> --source-sha256 <validate.py SHA256>
```

Mount the exact contract read-only at `/control/input-contract.json`, source read-only at `/code/validate.py`, originals read-only at `/artifacts`, and an existing empty writable directory at `/results`. The guard requires `/.dockerenv`, `CUDA_VISIBLE_DEVICES=''`, `NVIDIA_VISIBLE_DEVICES=void`, and no visible NVIDIA/render devices. There is no training, model loading, rollout, network call, or checkpoint-body read.

The agreed input schema is `{schema_version: 1, stages: [...]}`, ordered as `eval-teacher-locomotion`, `eval-teacher-low-step`, `eval-teacher-high-step`, `eval-teacher-low-climb-76`, `eval-teacher-high-climb-76`, `eval-student-pure`. Each stage contains `label`, `manifest`, `training_manifest`, `quality`, `config`, `log`, `events[]`, and `videos[]`. Every file record has `native_path`, `path`, `bytes`, and `sha256`; optional transfer fields such as `mode` are retained by the contract. `native_path` begins `/outputs/official-full/official/`; its absolute mapped `path` is `/artifacts/` plus the part after `/outputs/`. Each video also has `native_described: true`, `quality_bound: boolean`, and `declared_duration_seconds` taken from native `evaluation_videos`.

The 196 originals comprise six each of eval manifests, training manifests, quality reports, saved eval YAML files, event files and native logs, plus all 160 MP4 clips. Exactly 148 clips belong to `quality.videos` and native `artifact_fingerprints`; the remaining 12 early clips are native-described only. The validator preserves that distinction and attempts a full `ffmpeg` decode of every clip, including those 12. It requires actual child exit 0, positive frame counts matching `ffprobe`, and final `progress=end`; each child's command, wait result, complete stdout and stderr, metadata and measured failure remain in separate files. Each stage gets a PNG from the midpoint of its longest quality-bound original. Originals remain untouched.

Native checks bind final checkpoint identity and ordered teacher provenance through the six training and six evaluation manifests without loading PT files. They check official/passed/strict integer returncode 0, 64 environments × 3000 steps × 0.02 seconds, finite tracking fields, four metrics with 192000 samples apiece, reset sums, expert samples/resets and registry mapping. Expert and native command motion IDs are observations, not coverage claims. The pure student's actual `observed_clip_ids` are `[0,1,2,3,4]` while `available_clip_count` is 1: native `_sample_expert_balanced` assigns expert IDs to `motion_ids` inside a single motion bundle. V2 validates the reported fields without equating those two ID spaces. YAML checks use the actual saved fields; `training.checkpoint` is null in these originals, while the separate native CLI, manifests and quality JSON carry checkpoint identity.

Before constructing any EventAccumulator, v2 checks every full original event file with exact TFRecord little-endian length framing, masked header and payload CRC32C, bounded payload reads, complete EOF, unchanged file identity, and whole-file bytes/SHA. The `regular`, `masked_crc32c`, and `verify_tfrecord` functions are copied exactly from the frozen student extractor. `verifier-provenance.json` records original and copied-function hashes; the validator source hash pins the embedded code. Runtime dependencies are standard-library `hashlib`, `Path`, `stat`, `struct`, the shared `require` helper, the 64 MiB record bound, and installed TensorBoard `pywrap_tensorflow.crc_update`. The installed CRC module gets an actual before/after source fingerprint. `tensorboard-integrity.json` retains gate results and exact failure offsets. EventAccumulator then runs with restart purging disabled and requires the actual 17 `Evaluation/*` scalar tags at step 3000 to match quality scalars with absolute and relative tolerance `1e-6` for SummaryWriter float32 encoding. Success includes `tensorboard.value.event_integrity_complete: true` and per-file `event_integrity.events` with `status: passed`, `complete_eof: true`, and `crc32c_verified: true`.

V2 bounds ffprobe/ffmpeg decoder, encoder and filter threads to 1 for the host's two-CPU/256-PID container. This changes decoding resource use, not the preserved video inputs.

`/results/report.json` has `status: passed|failed`, six stage records, counts, scope, `quality_verified: false`, and `full: false`. Success means this CPU consistency/media audit passed; it says nothing about convergence, course completion or all source motions. A stage contains `native_quality`, `saved_yaml`, `tensorboard`, and `representative_thumbnail`, each `{status: passed, value: ...}` or `{status: failed, error: ...}`. Each video contains its own status and `ffprobe`/`ffmpeg` child records `{command, returncode, failure, elapsed_seconds}`. A successful thumbnail's `value.execution` uses the same child schema. Source, contract and all 196 inputs receive exact before/after SHA256 and byte snapshots; an admission mismatch or mutation fails the audit. The validator exits 0 only for a passed report, otherwise 1. A guard failure happens before third-party imports or child execution.

`source-manifest.json` freezes the prepared files and records read-only inputs and AST admission. `actual-input-observations.json` contains actual six-file JSON observations and verbatim saved YAML/native source text; it has no runtime pass status. `validate-v1-to-v2.diff` preserves the source changes. No dummy input contract, fabricated runtime result, or passed science report is produced here.
