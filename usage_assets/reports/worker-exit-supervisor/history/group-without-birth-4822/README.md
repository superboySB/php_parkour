The substantive fix rejects nonzero worker return codes after the polling loop. The old loop could miss a failure if all workers had already exited before its next condition check. Normal completion additionally requires each private worker process group to contain no observed non-zombie processes. This changes completion classification; it is not merely logging.

Each `Popen` uses `start_new_session=True`: expected PGID and SID equal its PID. The raw report retains this launch contract and actual `/proc` group/session/start identity when available. Cleanup waits for both the wrapper and its exact private group/session, so a wrapper exiting first cannot leave a native child unobserved. A remaining group receives SIGTERM, then SIGKILL if needed, followed by another bounded wait. Parent/unisolated groups are refused. A remaining or unobservable group fails and is never treated as cleaned up. Zombies are excluded from live membership; system-init reaping of orphan zombies is not claimed.

`worker-processes.json` records launch argv, identities, signed return codes/signals, group observations, and separate error-detection/final-wait times. Workers independently write `<role>-process-start.json` before loading their configuration. A shell wrapper can translate native SIGSEGV into positive exit code 1; that code does not identify a signal, and a worker entry receipt does not establish its later shutdown status. `/proc` identities belong to the observer namespace; `NSpid` may omit the outer host namespace. Optional `--python-faulthandler` enables tracebacks for a new cohort; inherited environment settings remain preserved and reported.

Stop-marker, diagnostic-write and log-close failures are deferred until reaping/close attempts finish, then propagated. They cannot turn a failed receipt into success. A previously written `result.json` may remain when final cleanup fails; the parent exit must still be nonzero and the driver must refuse to seal that attempt.
