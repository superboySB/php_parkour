# Quality retry integration audit (CPU only)

The gap is real. train_pipeline.py272–294 deliberately reruns an eval when a retained MP4/TB/quality artifact is deleted, altered or has old schema, but its eval argv465/473 and post-read396 always reuse `<stage>/quality.json`. The new eval_quality.py guard191–193 refuses that path whenever a previous file exists, including valid prior evidence. It also affects explicit reruns without --skip-completed, changed eval_steps/checkpoint, and failed attempts that left a quality file. The active frozen official0093 source is unchanged; this concerns future snapshots containing the guard.

An actual runc/networknone/no-GPU CPU container invoked the new native CLI on the first completed v3 quality path and its actual unchanged PT. The guard rejected it before native evaluator import with `Use a fresh quality output`. Docker exit was1 (the Isaac Python launcher normalizes argparse2 to1). Original report SHA and raw bytes remained unchanged. See reproduction.json, original stdout/stderr and container inspection.

The smallest compatible integration is to archive prior quality and its adjacent TensorBoard directory before any eval stage that is really being rerun, after valid skip decision but before child launch. Use a fresh `<stage>/quality-history/<time_ns>/` directory. Move/copy byte-exact existing quality.json and tensorboard/ into this history, verify SHA after retention, record original→retained paths/hashes in the new stage manifest, and keep the old manifest bytes already archived by the pipeline. Never delete evidence or rewrite historical JSON. Reject symlinks/nonregular quality paths. A malformed old report can still be archived by bytes without parsing it. Only remove the fixed fresh-path source after a verified copy, or atomic rename within the same filesystem. Failed retries retain both history and new partial output.

Archiving only quality.json is insufficient: QualityProbe enumerates all `<quality-parent>/tensorboard/events.*` files153–182, so otherwise the new report adopts earlier attempts' TB events. Archive the existing sibling tensorboard/ as well; keep timestamped MP4/native log folders unchanged, because fresh-video checks already exclude previous modification times. Record the TB relocation mapping so historical raw quality JSON continues to have an auditable resolution without editing its bytes.

An independent attempt directory for quality, TB and native logger output is cleaner for future formats, but it is a larger compatibility change now: pull_final_students.py248 has an exact whitelist requiring `official-full/official/eval-student-{kind}/quality.json`, although posttrain_coverage.py159 uses the manifest-recorded report path. A fresh quality basename alone still shares the same sibling TB folder. The compatible fixed-path archive above preserves the current selective-transfer contract and does not alter the long-running training/monitor snapshot.

Required regressions: valid --skip-completed makes no history/mutation; delete/tamper video or TB causes a fresh child path with prior quality bytes/history SHA preserved; malformed old quality is retained and rerun; changed eval steps/source PT can rerun; a failing child leaves previous history and current failed manifest; old TB files are absent from the fresh sibling folder and do not appear in the new report. The existing pipeline fake process overwrites an existing report, so it does not enforce the new native guard: make the process fixture assert its quality target does not exist before writing. Root can implement this independently; this audit changed no tracked source or frozen context.
