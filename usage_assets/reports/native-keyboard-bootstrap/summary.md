## Actual defect and narrowly scoped fix

The installed `sshkeyboard2.3.1` `listen_keyboard()` is synchronous, blocks until Escape/stop/error and returns `None`. Native `keyboard.py:105–129` then calls `.start()`/`.join()` on that return, including the TypeError fallback branch. This is a **listener-exit exception**; it does not establish that keys are dropped while the original blocking call is still running.

The root bootstrap imports the pinned native keyboard module, validates its whole-file SHA, live method SHA, dependency version/source SHA, listen alias and native delay constants, then replaces only `_KeyboardListenerThread.run` **in memory**. It preserves subscriber broadcasting, `0.15/0.05` delay arguments, first-call OSError handling and the TypeError fallback call. Unexpected errors, including fallback errors, still propagate. The fallback code is retained, but unknown dependency versions fail the compatibility gate rather than being declared supported.

The helper validates the actual installed native `run_policy.py` path and SHA, forwards CLI tokens unchanged, matches the native script's import-path entry and executes `runpy.run_path(..., run_name="__main__")`. Native SystemExit and errors propagate; temporary sys.argv/sys.path changes are restored. The shell wrapper continues its existing runtime activation and model/path resolution. This does not modify keyboard mappings, hold-to-move/pynput, DDS, ONNX inputs, PD, policy lifecycle or the original files. Changed dependencies/source require explicit re-review; the helper fails before patching rather than guessing.
